# ADR-0009: Shell redesign — single window row and persistent actions

## Status

Accepted

Частично заменяет:

- [ADR-0002](adr_0002_theme_persistence_and_beyond_plan_scope.md) §1–2 — модель темы: `System` становится явным сохраняемым выбором «Авто»; §3.3 — показ кнопок оболочки по наведению;
- [ADR-0003](adr_0003_post_m5_scope_new_document_and_app_menu.md) §3 — меню приложения слева сверху и его первый уровень; §4 — «UI-переход» настроек приложения внутри popover; §1 — в части recent files; §2 — в части кнопки `Создать MD` на welcome screen;
- [ADR-0007](adr_0007_folder_workspace_with_document_tabs.md), раздел «Architecture impact → Presentation» — правило «новых цветов в `Colors.axaml` не добавляется».

Уточняет: ADR-0007 Rule 4 — когда показываются вкладки.

## Date

2026-09-19

## Context

Оболочка вокруг документа сложилась по частям — M5–M6 из `ADR-0003`, затем папки и вкладки из `ADR-0007` — и к сентябрю 2026 выглядела так:

- над документом три слоя хрома: тайтлбар 36 px повторяет имя активной вкладки, под ним строка вкладок 34 px, поверх текста — плавающие группы кнопок, которые появляются только при наведении на окно;
- меню приложения живёт то плавающей кнопкой слева над текстом, то кнопкой в шапке сайдбара;
- тема (переключатель Light ↔ Dark), «Редактирование» и параметры чтения — три отдельные кнопки; настройки приложения спрятаны за цепочкой «Меню → Настройки → О приложении» с кнопкой «назад»;
- вкладки 120–240 px по содержимому обрезают даже короткие имена;
- внизу окна четыре подсказки клавиш с «Ctrl» — и на macOS тоже; подписи внизу набраны `MmTextFaintBrush` (около 3,5:1);
- тёмная тема: фон oklch 0,18 (`#14110E`), текст 14,8:1 — на длинном чтении светлые буквы «светятся»;
- светлая тема: акцент `#BD592F` даёт ссылкам 4,35:1 — ниже 4,5:1.

Редизайн проработан на холсте дизайна «Оболочка MarkMello» (https://claude.ai/artifact/GxVqzALqKfSqGMSrCfCYTL, заметка «Решения»). Из трёх направлений — A «Единая строка», B «Только текст», C «Вертикальные вкладки» — выбрано A: структура окна остаётся прежней, меняется только оболочка.

Что **не** меняется и остаётся обязательным:

- MarkMello — viewer-first; путь `open file -> readable document` не дорожает;
- рендер документа (`MarkdownDocumentView` и всё под ним) не трогается — меняются только оболочка вокруг него и значения цветовых токенов;
- ADR-0007 Rules 1, 2, 3, 10 и 11 действуют без ослабления: sidebar и workspace-подсистема существуют только в folder mode, welcome не становится project launcher, холодный старт ничего не открывает сам, вторая папка — новое окно.

## Decision

Оболочка MarkMello перестраивается по варианту A: **одна строка окна 44 px** с вкладками и постоянным блоком из четырёх кнопок справа; параметры чтения вместе с темой — в карточке **Aa**; редкие настройки приложения — в одной модальной карточке **«Настройки»**; на стартовом экране появляются **«Недавние»**.

## Rules

### 1. Одна строка окна 44 px

- Тайтлбар 36 px и строка вкладок 34 px сливаются в одну строку 44 px справа от сайдбара. Фон — `MmBackgroundBrush`, как у документа: отдельного цвета тайтлбара больше нет.
- На macOS строка 52 px — высота системного тулбара unified (уточнено 2026-09-19). Окно получает пустой `NSToolbar` в этом стиле, и macOS ставит светофор по центру строки, как у Finder, Почты и Заметок; без тулбара кнопки прижаты к верхнему краю окна.
- Текста заголовка в строке нет. `Window.Title` (`файл — папка — MarkMello`) сохраняется для Dock, панели задач и переключателя окон.
- `ExtendClientAreaTitleBarHeightHint` — высота строки: 44, на macOS 52.
- Платформы:
  - macOS — светофор в шапке сайдбара высотой со строку, пока сайдбар открыт; когда сайдбар свёрнут, папки нет или показан стартовый экран — светофор в самой строке слева;
  - Windows — собственные кнопки окна 46×44 справа в строке;
  - Linux — рамку рисует оконный менеджер, строка идёт под ней без кнопок окна.
- Пустое место строки и шапки сайдбара тянет окно (Windows, macOS); на Windows двойной клик разворачивает и восстанавливает окно.
- Под строкой всегда линия `MmBorderSoftBrush`, как под тулбарами Safari, Finder и Заметок.
- Внешнее изменение файла во вкладке с несохранёнными правками показывается полосой под строкой окна во всю ширину области документа, а не плашкой по центру поверх текста. Полоса висит до выбора «Загрузить с диска» (правки пропадут — это сказано в подсказке кнопки) или «Оставить мои правки». Без правок файл по-прежнему перечитывается молча.
- Новой полоски прогресса 2 px и надписи вида «34% · осталось 2 мин» под строкой нет. Существующая тонкая полоска прогресса 1 px у верхнего края документа остаётся как есть.
- Подсказки клавиш в строке состояния внизу окна убираются: сочетания живут в меню и тултипах. Внизу остаются слова и время чтения — одной плашкой «N слов · M мин» в правом нижнем углу области документа, на непрозрачной подложке `MmBackgroundBrush`, видной всегда, а не при наведении на окно (уточнено 2026-09-20 в MM-44). Время чтения считается по 200 слов в минуту с округлением вверх.
- Подвала сайдбара со счётчиком документов нет (уточнено 2026-09-20 в MM-44): число считалось по загруженным узлам дерева и менялось при раскрытии папок, а несохранённые документы и без него видны точкой в дереве и на вкладке.
- Короткие подписи (счётчик внизу, подпись под «Документ не выбран») набираются `MmTextSoftBrush` вместо `MmTextFaintBrush`; сам заголовок «Документ не выбран» — 22 px `MmTextBrush` (уточнено 2026-09-20 в MM-44).
- Сайдбар выравнивается по строке: его шапка той же высоты; строки дерева 28 px с иконками папок и файлов (было 26 без иконок); текущий файл отмечен заливкой `MmTabActiveBrush` и иконкой акцентом вместо полоски 2 px.
- Сетка краёв, одна для строки окна и сайдбара (уточнено 2026-09-19): подложки кнопок и вкладок и строки дерева стоят в 11 px от краёв окна и сайдбара, иконки и текст — в 19 px, на одной вертикали с красной кнопкой светофора macOS; шевроны дерева встают на ту же вертикаль. Поле поиска видно всегда, поэтому его рамка стоит по краям светофора и иконок — в 19 px. Слева и справа отступы одинаковые, карточки строки прижимаются к правому краю по тем же 11 px.

### 2. Постоянный блок действий справа

- В правой части строки всегда четыре кнопки-иконки 30×30, радиус 8: поиск (`⌘F`), Aa (параметры чтения), правка (`⌘E`), меню ⋯.
- Кнопки видны всегда. Показ кнопок оболочки при наведении на окно отменяется (заменяет ADR-0002 §3.3 в этой части) вместе с плавающими группами кнопок и плавающей кнопкой меню слева.
- Состояния: наведение — `MmTabHoverBrush`; кнопка нажата или её карточка открыта — `MmTabActiveBrush`.
- Карточки поиска, Aa и меню ⋯ раскрываются под своей кнопкой, у правого края: одно правило на всю строку. Поиск — карточка, а не плашка по центру поверх текста.
- В режиме правки карандаш на том же месте становится залитой кнопкой «Готово» (фон `MmTextBrush`) — единственной залитой кнопкой в строке; кнопки Aa в правке нет; рядом «Не сохранено ⌘S», пока есть несохранённые правки.
- Исключение — черновик без пути (`⌘N`, «Новый документ» в меню «+»): у него «Готово» нет, только «Не сохранено ⌘S», пока черновик не сохранён через «Сохранить как»; после этого появляется «Готово». Показ черновика в режиме чтения без сохранения по-прежнему не поддерживается.
- На стартовом экране и на вкладке с ошибкой загрузки справа только ⋯: искать и править там нечего.
- Сочетания в тултипах, меню и на стартовом экране подписываются по платформе одним помощником: `⇧⌘O` на macOS (модификаторы в принятом там порядке ⌃⌥⇧⌘), `Ctrl+Shift+O` на Windows и Linux.
- Overlay model из ADR-0003 §7 сохраняется: одновременно открыта одна карточка.

### 3. Вкладки показываются всегда, когда есть документ

Уточнение ADR-0007 Rule 4.

- Открытый документ — всегда вкладка: и в folder mode, и без папки. Отдельного вида «одного файла» нет.
- В single-file режиме вкладка — это тот же `OpenDocumentsViewModel` на один элемент, что и сейчас; workspace-подсистема и sidebar не создаются (ADR-0007 Rule 1 без изменений).
- После вкладок — кнопка «+». Она открывает меню-карточку из двух пунктов: «Открыть файл… ⌘O» и «Новый документ ⌘N» (уточнено 2026-09-26 в MM-73; до него «+» сразу создавал черновик, как `⌘N`, без меню). Открыть ещё один документ нужно чаще, чем создать новый, а `⌘O` мышью было доступно только через меню ⋯ — поэтому «Открыть файл…» стоит первым. Тултипа у «+» нет: меню само подписывает оба действия. Кнопка есть всегда, когда в строке есть вкладки; в folder mode без открытых вкладок в строке только «+»; на стартовом экране нет ни вкладок, ни «+».
- Требование ADR-0007 «полоса вкладок не должна становиться постоянным chrome: без открытых вкладок её нет» теперь относится к вкладкам, а не к строке: строка 44 px заменяет тайтлбар, а не добавляется к нему.
- Метрики: высота 30, радиус 8, ширина 180; когда тесно, вкладки сжимаются до 120, дальше лишние уходят в «ещё N»; промежуток между вкладками 6.
- Вкладка — плашка с заливкой вместо рамок и акцентной полосы: `MmTabBrush` → `MmTabHoverBrush` → `MmTabActiveBrush`. Несохранённые правки — точка `MmAccentBrush` 6 px в правом верхнем углу вкладки, в 6 px от её краёв (уточнено 2026-09-21 в MM-57): она видна и с иконкой, и с крестиком, лежит поверх раскладки, имя не сжимает и не сдвигает, и справа от имени не пустует зарезервированная под неё колонка. У длинного имени край под ней уже погашен затуханием. Анатомия: 8 · иконка/крестик 18 · 4 · имя · 8. Отвергнуты: точка в промежутке перед именем (сливается с первой буквой) и бейдж на углу крестика (путается с его линиями).
- Имя вкладки не обрезается многоточием, а у правого края плавно затухает маской прозрачности 24 px — только если имя вместе с « · папка» и «(удалён)» не помещается; ширина затухания не больше скрытого остатка, как у таблиц (уточнено 2026-09-21 в MM-57). Список «ещё N» по-прежнему обрезает имена многоточием и держит точку справа.
- Тултип вкладки — полный путь к файлу, домашняя папка сокращается до `~` (было: путь относительно корня папки, для файлов вне папки — абсолютный).
- Логика «ещё N», `Ctrl Tab`, дизамбигуации одноимённых файлов и сохранения прокрутки не меняется. Перетаскивания и закрепления вкладок нет, как и в ADR-0007.
- Неудачное открытие файла тоже создаёт активную вкладку — с именем файла и экраном ошибки в document surface (ADR-0007 Rule 14); сейчас ошибка показывается состоянием окна, и своей вкладки у неё нет. «Повторить» перечитывает путь этой вкладки и при успехе показывает документ в ней же; `Esc` и ✕ закрывают вкладку ошибки и возвращают к предыдущей. Вкладка ошибки не пишется в сессию окна и в «Недавние».
- Открытие документа — `⌘O`, `⌘N`, перетаскивание файла, клик по файлу в дереве — больше не спрашивает про несохранённые правки активной вкладки: документ открывается в новой вкладке, правки остаются в своей. Диалог несохранённых правок поднимается только тогда, когда вкладка с правками действительно закрывается или перечитывается.

### 4. Меню ⋯ справа

Заменяет ADR-0003 §3: кнопку меню в левом верхнем углу и первый уровень «Open file / Close file / Settings».

- Меню открывается под кнопкой ⋯ справа. Кнопки меню слева и в шапке сайдбара нет.
- В меню только команды с сочетаниями и вход в настройки, группы через разделители:
  - Новый документ `⌘N` · Открыть файл… `⌘O` · Открыть папку… `⇧⌘O`;
  - Сохранить `⌘S` · Сохранить как… `⇧⌘S` · Перечитать с диска `⌘R`;
  - Панель файлов `⌘B` · Закрыть вкладку `⌘W` · Закрыть папку;
  - Настройки… `⌘,` · Проверить обновления… · О MarkMello.
- «О MarkMello» — последний пункт, в своей группе после «Настройки…» (уточнено 2026-09-20 в MM-43). На macOS этого пункта в меню ⋯ нет: он в системном меню приложения, и дублировать его — против привычки платформы.
- «Проверить обновления…» — над «О Softmark», в той же группе и по тому же правилу: на macOS пункт в системном меню, в меню ⋯ его нет (уточнено 2026-09-26 в MM-74). Как и «О Softmark», он — исключение из «только команды с сочетаниями»: сочетания у него нет. Пункт виден всегда; что делает проверка — [ADR-0004](adr_0004_cross_platform_distribution_and_updates.md), «Update Model».
- Без папки «Панель файлов» и «Закрыть папку» скрыты; остальные неприменимые команды гаснут. «Закрыть файл» заменён на «Закрыть вкладку».
- Тема и размер текста в меню не дублируются — они в карточке Aa.
- Действия с папкой дублируются в сайдбаре: меню «имя папки ▾» (открыть другую папку, показать в файловом менеджере, закрыть папку) и «+» (новый файл, новая папка).
- Пункты меню ⋯ и меню сайдбара — 26 px, а не 30 px холста (уточнено 2026-09-20 в MM-44): так меню держит ритм системных меню macOS. Неприменимые пункты гаснут, но остаются на месте.
- Все меню приложения — карточки внутри окна на общей тени `MmCardShadow` (уточнено 2026-09-20 в MM-50): меню ⋯, меню «имя папки ▾», меню «+» сайдбара, контекстное меню строки дерева, список скрытых вкладок «ещё N» (уточнено 2026-09-21 в MM-56: он был попапом `Flyout` и рисовался карточкой в рамке `FlyoutPresenter`) и меню «+» у вкладок (уточнено 2026-09-26 в MM-73). Открытие, закрытие по `Esc` и клику мимо и правило «одновременно открыт не больше одного оверлея» у них общие. Попапами ОС они быть не могут: попап — отдельное окно ровно по размеру карточки, и `BoxShadow` обрезается его краем (проверено на macOS 2026-09-20 в MM-44), а поле под тень вокруг попапа съедало бы клики рядом с меню. Слой карточек меню сайдбара лежит поверх колонок и строки окна: карточка шире сайдбара иначе ушла бы под документ вместе с тенью. В нём же живут карточки строки окна: «ещё N» выровнена по правому краю своей кнопки, меню «+» у вкладок — по левому и у правого края окна сдвигается внутрь.
- Контекстное меню строки открывается у курсора, а с клавиатуры (`⇧F10` и клавиша «меню») — под выделенной строкой; у края окна карточка сдвигается внутрь, а не обрезается. Попапами ОС остаются только те меню, что принадлежат не оболочке: контекстное меню документа и список языков в окне «Настройки». Вид у них тот же, а тени по той же причине нет.

#### Системное меню macOS

Уточняет ADR-0003 §3 (уточнено 2026-09-20 в MM-43): там меню приложения решено не превращать в desktop-style full menu bar, и это в силе. Системное меню macOS — не такой menu bar: оно принадлежит приложению, а не окну, и его состав диктует платформа.

- Только macOS. На Windows и Linux меню приложения нет — все команды в меню ⋯.
- В меню «MarkMello» свои пункты — «О MarkMello» и под ним «Проверить обновления…» (второй добавлен 2026-09-26 в MM-74); «About Avalonia», который Avalonia ставит по умолчанию, убран. Системные Services / Hide / Hide Others / Show All / Quit остаются от Avalonia, вместе с их переводом.
- Подпись пункта — на языке приложения и меняется вместе с ним; системные пункты — как их даёт Avalonia.
- Меню строится на старте из двух пунктов, без сервисов: быстрый путь `open file -> readable document` не дорожает, окна About и обновления создаются только по нажатию.
- «Настройки… `⌘,`» в системном меню — вне рамок MM-43 и MM-74. `⌘,` по-прежнему ловит окно (`OnWindowKeyDown`).


### 5. Параметры чтения и тема — в карточке Aa

Разделение ADR-0003 §4 сохраняется: Aa — только чтение, настройки приложения — отдельно. В Aa переезжает тема, отдельная кнопка Light ↔ Dark удаляется.

- Состав сверху вниз: тема; шрифт; размер текста «− N px +»; интерлиньяж; ширина строки; внизу ссылка на окно «Настройки» (`⌘,`). Строки «Миникарта» нет (уточнено 2026-09-26 в MM-71): миникарта убрана из приложения, место у края документа отдано оглавлению.
- `⌘+` и `⌘=` увеличивают, `⌘−` уменьшает размер текста на 1 px в пределах 12–24, `⌘0` возвращает 14 (уточнено 2026-09-22 в MM-60: умолчания чтения — Sans 14 / 1,6 / 820); на Windows и Linux — `Ctrl`. Работают в чтении и в правке.
- Карточка по-прежнему создаётся лениво, по первому нажатию на Aa.

### 6. Тема: Авто / Светлая / Тёмная

Заменяет ADR-0002 §1 и вытекающую из него интерпретацию плана в §2.

- Пользователь выбирает одно из трёх значений: «Авто» (`ThemeMode.System`), «Светлая» (`Light`), «Тёмная» (`Dark`). Все три сохраняются.
- «Авто» — явный выбор, а не только fallback: приложение следует теме ОС на лету, без перезапуска.
- Формат `settings.json` не меняется: `ThemeMode` уже содержит `System = 0`. Существующие файлы читаются как раньше — нет значения или `System` → «Авто», `Light` / `Dark` → как сохранено.

Почему ADR-0002 §1 пересматривается: tri-state не был нужен, пока тема переключалась одной кнопкой Light ↔ Dark. Переключатель уходит в сегментированный выбор в Aa — и минус, записанный в самом ADR-0002 («пользователь не получает явную команду вернуться в persistent System mode»), становится видимым пробелом, который закрывается третьим сегментом без новой инфраструктуры.

### 7. Настройки приложения — одна модальная карточка

Заменяет «UI-переход» ADR-0003 §4 и цепочку «Меню → Настройки → О приложении».

- «Настройки» — модальная карточка внутри окна на общей рамке диалогов (Rule 10 ниже), не отдельное окно ОС. Одна страница без разделов.
- Открывается по `⌘,` (везде, включая стартовый экран), из меню ⋯ и из карточки Aa; закрывается `Esc` и ✕.
- Состав: подсказка, что тема, шрифт и размер — в карточке Aa; язык; рамка окна; оглавление; внизу версия, лицензия, автор и ссылки проекта. Раздела «Обновления» нет (уточнено 2026-09-26 в MM-74): проверка, загрузка и установка живут в меню приложения и окне обновления. Переключатель «Оглавление» Вкл/Выкл (уточнено 2026-09-26 в MM-72) — здесь, а не в карточке Aa: это редкий переключатель, который ставят один раз, а не параметр, который крутят во время чтения.
- Состояния `AppSettings` и `AppAbout` оверлейной модели сливаются в одно.
- «О MarkMello» выезжает из карточки в своё окно ОС (уточнено 2026-09-20 в MM-43) — единственное исключение из «окна только под папку»: на macOS About обязан открываться из системного меню, когда карточки «Настройки» на экране нет. Нижняя строка карточки — версия, лицензия, автор и ссылки — остаётся как есть и дублирует те же сведения. Окно About немодальное, не плодится вторым экземпляром и не держит приложение: когда закрыто последнее главное окно, `ShutdownMode.OnLastWindowClose` завершает его вместе с About.
- Уточнено 2026-09-23 в MM-68 ([ADR-0011](adr_0011_fork_identity_and_release_source.md)): приложение теперь Softmark. Нижняя строка карточки — имя, версия, лицензия и одна ссылка на GitHub форка; автора, сайта и телеграма оригинала больше нет. Окно About показывает те же сведения и строку атрибуции оригинала, которой в карточке нет.
- Окно обновления — второе исключение из «окна только под папку» (уточнено 2026-09-26 в MM-74): оно тоже открывается из системного меню macOS, когда карточек на экране нет. Как About, оно немодальное, в одном экземпляре и закрывается вместе с последним главным окном. Проверка обновлений — [ADR-0004](adr_0004_cross_platform_distribution_and_updates.md), «Update Model» (ADR-0003 §5 заменён).

### 8. «Недавние» на стартовом экране

Возвращает recent files, выведенные из ближайшего scope в ADR-0003 §1, с ограничениями.

- Стартовый экран — три действия: «Открыть файл…» (основное), «Открыть папку…», «Новый документ» (`⌘N`, бывшее `Создать MD` из ADR-0003 §2 — семантика черновика та же); под ними «Недавние».
- «Недавние» показываются только на стартовом экране — не в меню ⋯, не в Dock и не в JumpList.
- Файлы и папки, до 5 записей (уточнено 2026-09-19 в MM-34: при 8 экран не помещался в окно минимальной высоты), свежие сверху; повторное открытие поднимает запись наверх. Пока список пуст, блока нет.
- Пишутся явные открытия: файлы из диалога «Открыть», по ассоциации и из командной строки, перетаскиванием, через «Сохранить как», из самих «Недавних»; папки — при любом открытии. Не пишутся: файлы, открытые из дерева папки, неудачные открытия, черновики без пути.
- Хранение — новое поле в `settings.json`, общее для всех окон, с регистрацией типов в `MarkMelloJsonSerializerContext`; запись в фоне, как у параметров чтения; битое или отсутствующее поле — пустой список.
- Существование записей проверяется асинхронно, вне UI-потока, через абстракцию Application и только пока показан стартовый экран. При старте с файлом проверка не запускается.
- Холодный старт без аргументов ничего не открывает сам (ADR-0007 Rule 10 без изменений).
- Стартовый экран не становится project launcher (ADR-0007 Rule 2): три действия остаются главными, «Недавние» — список под ними; закрепления, групп, превью, поиска и настройки длины списка нет.

### 9. Цветовые токены

Заменяет правило ADR-0007 «новых цветов в `Colors.axaml` не добавляется».

Новые ключи — в обе `ThemeDictionaries` `Themes/Colors.axaml`:

| Ключ | Светлая | Тёмная | Назначение |
|---|---|---|---|
| `MmTabBrush` | `#F3EFEA` | `#2A2522` | неактивная вкладка |
| `MmTabHoverBrush` | `#ECE7E1` | `#322D29` | наведение на вкладку и кнопку строки |
| `MmTabActiveBrush` | `#E2DBD4` | `#423C37` | активная вкладка, нажатая кнопка, текущий файл в дереве |
| `MmScrimBrush` | `#47201915` | `#80000000` | единый скрим модальных диалогов |
| `MmCardShadow` | `0 18 48 -12 #3D38281C, 0 2 6 #0F38281C` | `0 18 48 -12 #A6000000, 0 2 6 #4D000000` | тень карточек над документом: поиск, Aa, ⋯, меню, диалоги, список языков (добавлен 2026-09-20 в MM-44) |
| `MmQuoteBackgroundBrush` | `#F4F0EA` | `#29241F` | плашка цитаты и фон шапки таблицы (добавлен 2026-09-22 в MM-60) |

| `MmScrollThumbBrush` | `#521F1915` | `#4DE7E4DF` | ползунок полосы прокрутки: `MmTextBrush` при 32 % и 30 % (добавлен 2026-09-27 в MM-54) |
| `MmScrollThumbHoverBrush` | `#801F1915` | `#73E7E4DF` | ползунок при наведении и перетаскивании: `MmTextBrush` при 50 % и 45 % (добавлен 2026-09-27 в MM-54) |

Удаляются вместе с тайтлбаром: `MmTitleBarBrush`, `MmTitleBarTextBrush` и ресурс высоты `MmTitleBarHeight`.

Тёмная тема светлее:

- фон oklch 0,18 → 0,23 (`#14110E` → `#201C19`) — светлота тёмных окон VS Code и Windows 11, только тёплая;
- поверхности, рамки, код, цитаты, клавиши, выделение и подсветка поиска получают ту же прибавку ΔL +0,05 при прежних цветности и тоне — ступени между фоном, сайдбаром, кодом и карточками сохраняются;
- вторичный текст 0,70 → 0,73, бледный 0,55 → 0,59; `MmTreeInertTextBrush` в тёмной теме по-прежнему равен `MmTextSoftBrush` и меняется вместе с ним (`#A29E98` → `#ABA7A1`), в светлой остаётся `#6F6A65`;
- `MmTextBrush`, `MmAccentBrush` и `MmAlert*Brush` не меняются; контраст основного текста 14,8:1 → 13,3:1.

Светлая тема не меняется, кроме акцента: oklch 0,58 → 0,55 (`#BD592F` → `#B35025`), ссылки на фоне 4,35:1 → 4,9:1.

Документ берёт цвета из тех же токенов, поэтому его фон, текст и блоки кода в тёмной теме тоже станут светлее; код рендера при этом не меняется.

Правило на будущее: новый цвет вводится только ключом сразу в обеих темах, значения считаются из oklch тем же способом, что и остальная палитра; наборы ключей светлой и тёмной темы совпадают, и это проверяется тестом.

### 10. Один скрим для всех модальных диалогов

- Все модальные карточки — несохранённые правки, удаление, «Настройки», подтверждения на стартовом экране — лежат на одном скриме `MmScrimBrush`.
- Скрим накрывает всё окно, включая сайдбар, вкладки и строку; клики под ним не проходят.
- Верхняя полоса скрима высотой со строку окна тянет окно (Windows, macOS): окно остаётся перетаскиваемым, хотя скрим больше не начинается под тайтлбаром.
- Карточка 440 px, радиус 12; кнопки 32 px, радиус 8; основная кнопка залита `MmTextBrush`, опасная — `MmAccentBrush`. Стиль диалоговых кнопок живёт в `Themes/Controls.axaml`.
- Порядок кнопок и клавиши подтверждения следуют платформе.

### 11. Перетаскивание папки при открытой папке — новое окно

ADR-0007 Rule 11 не меняется: надпись макета «папка откроется вместо текущей» не принимается.

Слой перетаскивания накрывает всё окно и заранее говорит, что произойдёт: файл откроется в новой вкладке, папка — в новом окне, папка уже открыта в другом окне. Если список файлов недоступен до отпускания, пояснения нет.

### 12. Быстрый путь не дорожает

- Карточки Aa, поиска, меню ⋯, «Настройки» и диалоги создаются по первому действию пользователя, а не на старте.
- Строка 44 px в single-file режиме не монтирует sidebar и не создаёт workspace-подсистему.
- «Недавние» — поле в `settings.json`, который и так читается синхронно до первого окна; проверка существования записей идёт только на стартовом экране и вне UI-потока.
- Шаг, который меняет то, что создаётся на старте single-file сценария (строка окна, вкладка, стартовый экран, чтение `settings.json`), подтверждается замером до и после (`--smoke-exit-after-open`, `tools/measure-startup.ps1`); без замера — вопрос к автору на ревью, а не блокер.
- По завершении редизайна обязателен контрольный замер single-file сценария относительно baseline из [плана папок и вкладок](../implementation-plan-folders-tabs.md): расхождение в пределах шума по методике плана (±10 % по времени, ±5 МБ по памяти).

## Rejected alternatives

### A. Вариант B «Только текст»

Постоянного хрома нет: сверху имя документа, управление — капсула снизу, появляется при движении мыши; файлы — панель поверх текста; всё остальное — палитра `⌘K`.

Отклонено: функции труднее найти, показ по движению мыши возвращает ту самую проблему прячущихся кнопок, а палитра как основной путь к командам — новая подсистема, которая тянет продукт к IDE.

### B. Вариант C «Вертикальные вкладки»

Открытые документы — вверху сайдбара, под ними дерево; сайдбар переключается на оглавление документа.

Отклонено: sidebar существует только в folder mode (ADR-0007 Rule 3), поэтому в single-file режиме вкладок не было бы совсем; оглавление добавляет сайдбару второй режим. Вариант лучше всего для папок с десятками файлов — это не основной сценарий MarkMello.

### C. Другие места для настроек

- Панель справа со всеми настройками — забирает 340 px, в окне 1280 с сайдбаром «Широкая» строка уже не помещается; редкое смешано с частым.
- Отдельное окно настроек с разделами — документ под затемнением, эффект ширины строки и миникарты виден только после закрытия; до шрифта два шага.
- Всё в меню ⋯ — меню длинное и смешивает команды с настройками; параметры чтения разъезжаются по двум местам.

Выбрана карточка Aa у документа: шрифт, размер и тема — в один клик, документ не сжимается и не затемняется, ширину строки видно такой, какой она будет. Цена — четвёртая иконка в строке.

### D. «Настройки» отдельным окном ОС

Отклонено: второй тип окна ОС требует своей модальности на трёх платформах и ещё одной ветки в DI поверх мультиоконной схемы ADR-0007. Модальная карточка на общей рамке диалогов даёт то же поведение без новой инфраструктуры.

### E. Плашка «одного файла» без вкладок и «+»

Макет single-file режима показывал документ одной плашкой без «+»; «Новый документ» при этом заменял бы текущий.

Отклонено: один и тот же документ выглядел бы по-разному в двух режимах, а замена текущего документа новым противоречит правилу «правки остаются в своей вкладке». Одно правило для всех режимов проще.

### F. Прогресс чтения в строке

Полоска прогресса 2 px и «34% · осталось 2 мин» под строкой при прокрутке.

Отклонено: ещё один постоянно меняющийся элемент над документом ради сведений, которые уже дают тонкая полоска прогресса, миникарта и время чтения в строке состояния.

## Consequences

### Positive

- над документом одна строка вместо трёх слоёв хрома; кнопки не прячутся и не переезжают;
- тема, шрифт и размер — в одном месте в один клик, редкие настройки — в одном предсказуемом окне;
- сочетания подписаны так, как они выглядят на клавиатуре пользователя;
- тёмная тема перестаёт быть самым тёмным окном на экране, ссылки в светлой теме проходят 4,5:1;
- у всех модальных диалогов одна рамка и одно поведение;
- «Недавние» закрывают частый сценарий «вернуться к вчерашнему документу» без project-модели.

### Neutral

- рендер документа не меняется, но его цвета в тёмной теме меняются вместе с токенами; это влияет на контраст Mermaid-диаграмм в тёмной теме, который разбирается отдельно;
- `ThemeMode.System` из внутреннего fallback превращается в пользовательский выбор — формат настроек тот же.

### Negative

- четыре иконки видны постоянно — в правом верхнем углу больше постоянного интерфейса, чем при показе по наведению; противовес — тихие иконки без заливки и отсутствие строки заголовка;
- в узком окне с сайдбаром карточка Aa закрывает правый край текста;
- почти все шаги редизайна правят `Views/MainWindow.axaml`: параллельная работа требует частых ребейзов;
- ADR-0002, ADR-0003 и ADR-0007 теперь читаются вместе с этим ADR.

## Implementation sequence

Каждый шаг — отдельный PR в `develop`; шаги одной волны можно вести параллельно.

1. **Волна 0** — этот ADR.
2. **Волна 1** — цвета (Rule 9); подписи сочетаний по платформе и подписи `MmTextSoftBrush`; карточка Aa с темой и `⌘+` / `⌘−` / `⌘0` (Rules 5–6).
3. **Волна 2** — строка окна 44 px, блок кнопок справа, новый сайдбар (Rules 1–2).
4. **Волна 3** — вкладки (Rule 3); карточка поиска; кнопка «Готово» в правке; модальные диалоги на общей рамке (Rule 10). Потеря несохранённых правок при закрытии окна, папки и удалении чинится до диалогов.
5. **Волна 4** — состояния оболочки (внешнее изменение, ошибка загрузки, перетаскивание); окно «Настройки» и меню ⋯ (Rules 4, 7); стартовый экран и «Недавние» (Rule 8).
6. Контрольный замер single-file сценария относительно baseline (Rule 12).

## Final statement

```text
one window row -> tabs + four persistent actions -> the document stays in the center
```

MarkMello остаётся быстрым viewer-first Markdown-приложением. Редизайн убирает лишние слои хрома и делает действия постоянными и предсказуемыми, не добавляя новых подсистем на быстрый путь и не трогая рендер документа.
